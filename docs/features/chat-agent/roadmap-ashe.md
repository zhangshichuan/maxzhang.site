# Chat Agent Roadmap

## 1. 目标

本 roadmap 用于指导 `/chat` 从“外部接口转发聊天”演进为“基于 LangChain 的个人知识库智能客服”。

路线遵循两个原则：

- 先做稳定可展示的 RAG，再增强 Agent 能力
- 先做与当前站点高度贴合的能力，再考虑通用扩展

## 2. 里程碑概览

### Milestone 0: 现状梳理与重构准备

目标：

- 明确现有 `/chat` 可复用和需删除的部分
- 明确知识源入口
- 明确新的服务端返回结构

交付物：

- 重构方案文档
- 新的数据流设计
- 待删除旧逻辑清单

### Milestone 1: 本地知识库 MVP

目标：

- 从文章、个人介绍、README 中构建统一知识文档
- 建立文档切片和 metadata 规范

交付物：

- 知识源读取模块
- `Document` 构建逻辑
- 切片与标准化结果

验收标准：

- 能读取中英文文章
- 能读取个人介绍信息
- 能读取 README / ARCHITECTURE
- 每个 chunk 含 `type`、`locale`、`title`、`url` 等 metadata

### Milestone 2: RAG 问答链路

目标：

- 打通从问题输入到检索、生成、结构化输出的主流程

交付物：

- 问题分类逻辑
- retriever
- LLM 调用封装
- 统一响应结构

验收标准：

- 能回答文章相关问题
- 能回答个人介绍相关问题
- 能输出来源列表
- 知识不足时可拒答

### Milestone 3: `/chat` 页面重做

目标：

- 用新的个人知识库客服体验替换旧聊天界面

交付物：

- 新聊天 UI
- 首页态引导
- 来源卡片
- 相关文章推荐区

验收标准：

- 页面仍保留在 `/chat`
- 首屏能清楚表达用途
- 回答和来源展示分离
- 体验比纯文本聊天更像一个 RAG 产品

### Milestone 4: 双语与推荐能力

目标：

- 强化多语言体验和文章推荐效果

交付物：

- locale 优先检索
- 双语提示词策略
- 推荐文章逻辑

验收标准：

- 中文问题默认中文回答
- 英文问题默认英文回答
- 可以返回 2 到 3 篇相关文章

### Milestone 5: 可演示性增强

目标：

- 把项目从“能用”提升到“能讲”

交付物：

- 样例问题集
- 架构图或流程图
- 测试覆盖
- 文档补充

验收标准：

- 有清晰 demo 路径
- 有可复现测试
- 有可以面试展示的技术说明

## 3. 分阶段实施计划

## Phase 1: 重建服务端基础

### 任务 1. 删除旧聊天上游依赖

说明：

- 废弃当前 `fetch('http://host.docker.internal:8000/...')` 逻辑
- 保留 `/chat` 路由入口
- 重新定义 chat feature 的服务边界

预期结果：

- 聊天逻辑不再依赖外部容器接口

### 任务 2. 设计新的返回模型

说明：

- 从“纯流式文本”调整为“结构化结果优先”
- 让前端可以展示 `answer`、`sources`、`relatedPosts`

预期结果：

- 形成稳定的数据契约

### 任务 3. 确定模型与环境变量方案

说明：

- 明确 LLM 与 embedding 使用方式
- 明确 `.env` 中需要的配置

建议：

- 首版优先使用单一模型提供 generation
- embedding 与 generation 解耦，避免后续替换成本过高

## Phase 2: 知识库构建

### 任务 1. 文章知识抽取

说明：

- 基于现有文章读取逻辑抽取文章内容
- 输出标准化文档结构

细项：

- 读取 title / summary / tags / category / content
- 建立文章 URL
- 生成 `post` 类型 metadata

### 任务 2. 个人资料知识抽取

说明：

- 从 `messages/*.json` 和 about 相关内容抽取个人信息

细项：

- 技术栈
- 工作经历
- 教育经历
- 个人描述

### 任务 3. 项目知识抽取

说明：

- 从 `README` 和 `ARCHITECTURE` 补充项目背景知识

细项：

- 技术栈
- 架构原则
- 项目目标

### 任务 4. 文本切片与 metadata 规范

说明：

- 制定 chunk 粒度
- 明确不同类型文档的分片策略

建议：

- profile chunk 偏大，保留上下文
- post chunk 按标题和段落切分
- project chunk 中等长度，避免过碎

## Phase 3: RAG 主链路

### 任务 1. 查询分类

说明：

- 在进入检索前先做问题分类

分类建议：

- `profile`
- `post`
- `project`
- `recommendation`
- `out_of_scope`

### 任务 2. 向量检索

说明：

- 根据问题类型选择检索范围
- 优先召回对应语言内容

建议：

- 先做简单 top-k
- 后续再考虑重排

### 任务 3. 回答生成

说明：

- 将检索结果注入提示词
- 返回可控答案

要求：

- 禁止脱离知识库自由发挥
- 知识不足时拒答
- 输出语言跟随用户问题

### 任务 4. 来源与推荐输出

说明：

- 从检索结果和文章元信息中提取来源
- 生成相关文章列表

要求：

- 避免重复来源
- 推荐文章优先来自当前语言

## Phase 4: 前端体验重构

### 任务 1. 重做聊天首页态

说明：

- 增强“这是什么”的表达能力

内容建议：

- 说明文案
- 快捷提问
- 能力范围提示

### 任务 2. 重做消息展示

说明：

- 助手消息不只是一段文字

展示建议：

- 回答正文
- 来源区域
- 相关文章区域

### 任务 3. 错误与边界提示

说明：

- 针对拒答、无结果、服务异常分别设计文案

要求：

- 不要只显示通用 network error
- 让用户知道下一步能问什么

## Phase 5: 质量与演示增强

### 任务 1. 测试建设

优先测试：

- 知识文档构建
- 问题分类
- 拒答逻辑
- 服务层输出结构
- server action 转发

### 任务 2. 样例问题集

建议准备：

- 个人介绍类问题
- RAG / LangChain / LLMOps 类问题
- 文章推荐类问题
- 越界问题

### 任务 3. 项目文档补充

建议新增：

- RAG 架构说明
- 知识源说明
- Prompt 设计原则
- 演示截图或流程图

## 4. 技术优先级

### P0

- 替换旧聊天服务
- 本地知识源读取
- LangChain RAG 问答
- 来源引用
- 拒答机制

### P1

- 双语检索优化
- 相关文章推荐
- 首页态快捷提问
- 测试完善

### P2

- query rewrite
- 检索结果重排
- 对话记忆
- 更细的问题分类

### P3

- tool calling 扩展
- 多路工作流
- 多渠道接入

## 5. 风险与应对

### 风险 1. 先上复杂 Agent，导致实现失控

问题：

- 容易把时间花在框架调试上
- 首版难以做出稳定效果

应对：

- 首版坚持“轻 Agent、重 RAG”

### 风险 2. 知识源建模过于粗糙

问题：

- 检索结果不稳定
- 难做来源引用和推荐

应对：

- 一开始就区分 `profile` / `post` / `project`
- 统一 metadata 结构

### 风险 3. 回答像通用 AI，缺少作品辨识度

问题：

- 项目无法体现站点特色
- 面试讲解价值下降

应对：

- 强化来源、推荐、范围限制和个人知识库定位

### 风险 4. UI 只像普通聊天框

问题：

- 看不出 RAG 特征

应对：

- 明确展示来源和相关文章
- 加入首页态引导问题

## 6. 推荐实施顺序

建议按以下顺序推进：

1. 删除旧服务端转发逻辑，重定 chat 数据模型
2. 建立知识源读取与文档切片
3. 打通 LangChain RAG 主链路
4. 重做 `/chat` 页面
5. 增加来源与相关推荐
6. 补测试和项目文档
7. 再考虑 Agent 化增强

## 7. 完成定义

满足以下条件后，可视为首版完成：

- `/chat` 已完全替换旧流程
- 能回答站内文章与个人介绍相关问题
- 能明确拒答无关问题
- 能附带来源
- 能推荐相关文章
- 能中英文工作
- 有基础测试覆盖
- 有足够清晰的文档支持面试展示
