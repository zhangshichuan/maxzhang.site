# 摄影作品模块与独立存储服务

摄影模块以“作品”为内容单元（一条作品可含 1～N 张照片，轮播展示，共用一个图注和评论区），需要上传、图片加工与对象存储能力。为此新增一个独立的 NestJS 存储服务：接收上传、完成图片加工、读写对象存储；Web 端继续持有 SQLite 元数据（作品、图注、拍摄参数、评论）。存储服务通过 `StorageProvider` 接口解耦后端，v1 使用服务器本地磁盘（免备案），七牛等厂商适配器保留，后续可快速接入，甚至同时写多家。

Status: proposed

## Considered Options

- **浏览器直传对象存储**：上传省带宽，但加工必须把原图拉回服务端，增加回调、临时对象和额外流量，复杂度不成比例。
- **Web 直接调用厂商 SDK**：厂商细节会渗入业务层，违背解耦目标。
- **多厂商免费额度聚合**：永久免费额度有限，且大陆/国际访问质量差异大；用户选择单后端起步，但保留扩展能力。

## Consequences

- 上传链路固定为：浏览器 → Web server function（口令鉴权）→ 内网存储服务（API key）→ 七牛。
- 新增一个 Docker Compose 服务，仅内网可达，不暴露公网端口。
- 将来切换或增接厂商时只新增适配器，Web 与加工逻辑不变。
