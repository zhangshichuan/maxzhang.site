# 静态内容体系（MZ/OS 版）

> 本文是 maxzhang.site 静态文案的唯一策略文档；逐字字符串以
> `apps/web/messages/{zh,en}.json` 为准。中文与英文同结构、同语气。

## 0. 如果乔布斯来做这个网站

不是问「放什么内容」，而是问「**删到什么程度，它才只剩一个观点**」。

| 原则                 | 在网站上的具体动作                                                                                   |
| -------------------- | ---------------------------------------------------------------------------------------------------- |
| **Focus**            | 只讲一件事：把模型能力翻译成人们愿意用的产品。所有页面都为这句话服务。                               |
| **Say no**           | 删掉课程叙事、转型叙事、技能云、经历长文、多余 CTA、无用标签。导航从 5 项减到 3 项。                 |
| **Simplicity**       | 首页 = 一句话 + 三个数字 + 一个案例 + 四条方法 + 一组写作 + 一个终端。没有轮播、没有弹窗、没有花活。 |
| **Show, don't tell** | 网站本身是一个可操作的界面：系统栏、面板、状态、命令面板。设计就是产品演示。                         |
| **One more thing**   | 首页终端：输入 `help`、`work`、`notes`、`about`、`contact`。这是留给愿意深挖的人的彩蛋。             |

## 1. 定位

**一句话**：把模型能力，翻译成人们愿意用的产品。

**身份**：Max Zhang，AI 产品经理。十年全栈工程，两年把多智能体系统从 0 带到生产。

**对谁讲**：正在招 AI 产品经理的团队；AI 产品同行；被产品写作吸引的读者。

**希望记住的三件事**：

1. 他先定义任务，再挑模型。
2. 他用工程能力做取舍，而不是堆术语。
3. 他有一个可验证的案例：广告素材 Agent 工作流，效率 +80%，单条成本 2.5–3 元 → 0.5–1 元。

**口径**：不写课程、学习、转型；不写没有证据的客户与结果；数字只来自可核对的项目记录。

## 2. 信息架构

### 导航

- 桌面系统栏：`MZ/OS` + 当前路径 + **概览 / 写作 / 关于** + 搜索、更多、语言。
- 移动端 Dock：概览 / 写作 / 关于 / 更多。
- 更多：摄影、树洞、搜索、语言（低频入口，不占主导航）。

### 首页（`/`）

按「一句话 → 证据 → 信念 → 方法 → 写作 → 交互」推进：

1. **Hero**：身份 + 一句话 + 一句解释 + 两个动作（写邮件 / 阅读写作）。
2. **KPI**：三个数字（10+ 年 / 0→1 / +80%）。
3. **CASE_01**：一个案例，四行（场景 / 决策 / 结果 / 我的角色）。
4. **PRINCIPLES**：三条判断，每条一句话。
5. **METHOD**：四步（定义问题 / 做原型 / 设计评估 / 推进交付）。
6. **WRITING**：最新 3 篇文章 + 全部写作入口。
7. **TERMINAL**：可输入命令的彩蛋面板。
8. **CONTACT**：一句邀请 + 邮件 / GitHub。

### 写作（`/posts`）

- 标题 + 一句描述 + 写作计划（三个系列）+ 文章列表 + 分类/标签面板。
- 不写发布日期之外的承诺；系列只写方向，不写排期。

### 文章（`/posts/$slug`）

- 路径式 kicker（`~/notes/{slug}`）+ 标题 + mono 元信息 + 正文。
- 正文优先可读性：留白、代码块、表格、脚注；不加装饰性元素。

### 关于（`/about`）

- 两句话自述 + 一张灰度头像。
- INFO 面板：角色 / 所在地 / 关注 / 状态 / 邮箱。
- EXPERIENCE：四段经历，每段一行职责 + 一行结果。
- 联系面板。

### 其他

- 摄影 / 搜索 / 树洞 / 管理后台：保持功能，不进入主叙事；只用系统新 token 重新着色。
- 404：`command not found` + 一句解释 + 回概览。

## 3. 语气与写法

**中文**

- 第一人称，现在时；说「我做 / 我判断 / 我评测」。
- 短句，动词开头；一句只装一件事。
- 产品语言：任务、边界、取舍、评测、兜底、成本、交付。
- 禁用：赋能、抓手、闭环、颠覆、革命性、最强、首个（无证据时）。
- 数字必须可核对；没有证据就删掉那句话，而不是把它写虚。

**English**

- First person, present tense; short sentences; sentence case.
- Plain product English; no hype words.
- Mirror the meaning, not the word order.

**双语**

- 中文与英文信息量一致；中文更短，英文更直。
- 专名统一：AI 产品经理 / AI Product Manager；写作 / Writing；树洞 / Tree Hole。

## 5. 编辑清单

写任何一句静态文案之前，先过一遍：

1. 这句话删掉，网站会不会少一个观点？不会 → 删。
2. 这句话能不能换成数字或一个具体案例？能 → 换。
3. 这句话是不是在解释「为什么做」而不是「做了什么」？不是 → 改成 why。
4. 这句话里有没有可以从任何 AI 产品网站抄来的词？有 → 重写。
5. 首页每增加一个区块，是否删掉了一个旧区块？没有 → 先别加。

**首页只保留一个主动作按钮**（写邮件）；其他都是导航或信息，不做 CTA 堆叠。
