> 本文是 maxzhang.site 全站静态文案的**策略与结构文档**；所有逐字字符串以
> `apps/web/messages/{zh,en}.json` 为准，中文为主、英文同结构镜像。
> 上一版通用文案 `docs/copy/COPY_DECK.md` 仅作历史参考。

## 0. 这份文档解决什么

站点讲一个人：**Max Zhang，10 年以上全栈经验的 AI 产品经理**。页面结构从「自我介绍」升级为「知识地图 + 案例库 + 工程证据」：

1. 站点讲什么、对谁讲、用什么语气讲；
2. 每个页面的静态文案结构（不包含文章正文）；
3. 案例、判断、数字的口径与真实性边界；
4. 后续改文案时，改哪里、保持什么规则。

## 1. 定位与主题

**一句话**：把十年全栈的工程判断，翻译成 AI 产品能力。

**主题**：一张 4 阶段、13 个模块的知识地图，六个行业案例，一套能力模型。全部用第一人称写，是「我怎么做 AI 产品」，不是「我在学什么」。

**对外身份**：Max Zhang，10 年以上全栈工程经验，AI 产品经理。过去两年主导多智能体系统从 0 到生产落地。

**希望访客记住的三件事**：

1. 他有产品判断：场景、边界、评测、成本，能说清为什么这么做。
2. 他有一张完整的知识地图，不是零散知识点。
3. 他做过真实工程交付，能把方案和工程、算法聊到底。

**口径边界**：案例与数字按「项目记录」表述；不写客户名称、不编造未发生的结果；个人经历按本人确认口径。学习过程不出现在站点文案里。

## 4. 文案规则

### 写作习惯

1. **先问场景，再谈模型**：每条判断都要有「什么情况下不适用」。
2. **用产品语言**：边界、取舍、评测、兜底、成本、交付、验证；不用「赋能、抓手、颠覆、革命性」。
3. **术语必须能解释**：出现 RAG、MCP、Function Call、AB、灰度时，配一句人话或放在方法标签里。
4. **数字按项目记录写**：如「106 条主诉」「8 维 0/1/2 评分」「V0.11 0.75 → V0.13 0.775，80 分以上 66.7% → 40%」「630 人 / 3 次 / 3 个月」。不写没有记录支撑的数字。
5. **第一人称、现在时**：说「我做过 / 我判断 / 我评测」，不用「我在学 / 我准备转 / 教程教我」。

### 中文

- 短句，动词开头；能删的形容词都删。
- 标题偏判断句，正文偏解释句；不喊口号。
- 双语专名统一：AI 产品经理 / AI Product Manager；知识地图 / Knowledge Map；实战案例 / Case Studies。
- 按钮动词开头：看知识地图 / 看实战案例 / 打开完整地图 / 发邮件。

### English

- Sentence case, active voice, short sentences.
- Plain product English; avoid hype words.
- Mirror meaning, not word order; keep terms consistent with Chinese.
- First person, present tense: "I built / I judged / I evaluate", never "I'm learning" or "I'm transitioning".

## 5. 页面文案（摘要，逐字以 JSON 为准）

### 5.1 首页

**Hero**

- eyebrow：`AI Product Manager · 2026`
- 主标题：`十年全栈，` / `一套产品判断。`（渐变）
- 导语：`十年以上全栈工程经验，做 AI 产品。我把做过的六个行业案例，拆成一张能用的知识地图——从提示词、评测、RAG、Agent，到需求、市场、数据，再到教育、客服、医疗、旅游的落地判断。`
- 按钮：`看知识地图` → `/curriculum`；`看实战案例` → `/cases`；文字按钮 `写邮件`
- 元信息：`01 / 背景 · 十年全栈工程 · 多智能体系统`｜`02 / 作品 · 知识地图 · 6 个行业案例`｜`03 / 状态 · AI 产品经理 · 成都 / 远程`

**01 三条判断**（side：我在项目里反复验证的）

1. 先分场景，再选模型 —— 大模型擅长复杂、模糊、数据丰富的问题；高实时、零容错、简单大量的活，交给规则、小模型或者人。
2. 先写标准，再谈效果 —— 先定义什么算成功、失败怎么兜底、样本从哪里来；跑分高不等于产品能用。
3. 工程底子的价值是取舍 —— 把模型能力翻译成成本、风险和交付节奏。

**02 知识地图（4 个阶段）**

| 编号 | 模块  | 标题       | 一句话                                     | 方法标签                                                         |
| ---- | ----- | ---------- | ------------------------------------------ | ---------------------------------------------------------------- |
| 01   | 01–02 | 认知与原型 | 先把角色、模型边界和第一个 MVP 想清楚。    | 能力模型 / 大模型能力与幻觉 / 零代码 MVP / 提示词与评测          |
| 02   | 03–04 | 技术底座   | RAG 接知识，Agent 接行动。                 | 知识库五步 / 检索优化 / Function Call / MCP / 记忆与规划         |
| 03   | 05–08 | 产品全流程 | 从需求证据到 PRD，再到数据与合规。         | 访谈与问卷 / 市场选择 / PRD 与需求池 / 埋点 AB 灰度 / 沟通与合规 |
| 04   | 09–13 | 行业实战   | 把方法放进真实行业，最后写成可验证的项目。 | 教育答疑 / 智能客服 / 会议纪要 / AI 问诊 / 旅游规划 / 求职包装   |

**03 实战案例（3 个预览）**

1. AI 智能客服（零售 / 客服）——先分流，再回答；情绪兜底独立于业务意图。
2. AI 旅游规划师（旅游 / 规划）——用户要的不是信息，是一份能直接执行的方案。
3. AI 拍照搜题（教育 / 工具）——先给结果，再在后台校验题库答案。

**04 工作方式**：定义问题 → 画工作流 → 定评测 → 推落地；底行：`工程底子 · TypeScript · Python · Go · 多智能体（MCP / A2A）· 可观测性`。

**05 精选文章**：工程手记，和 AI 产品复盘。

**Now**：正在拆新的 AI 产品案例、更新知识地图，也在看合适的 AI 产品机会。
**联系**：聊聊 AI 产品。如果你们在做 AI 产品，或者想聊聊 Agent、RAG 与评测，欢迎直接邮件。

### 5.2 知识地图页（`/curriculum`）

- 标题：`知识地图`
- 副标题：`我的 AI 产品知识地图：4 个阶段、13 个模块，从模型边界到行业落地。`
- 说明：`这张地图只保留我能讲清楚、做项目时会实际调用的方法；讲不透的细节不写。`
- 13 个模块，每个四件事：编号 + 标题、一个问题、方法标签、产出物。全部条目见 `messages/zh.json` 的 `CurriculumPage.stages`。
- 能力模型 5 维：场景与需求 / 方案与工作流 / 评测与数据 / 技术与成本 / 落地与表达。
- 使用说明：`这不是教程。每个模块只保留我做 AI 产品时会用到的判断；没踩过的坑，不写。`
- CTA：地图之外，是六个具体案例。

### 5.3 实战案例页（`/cases`）

- 标题：`实战案例`；副标题：`六个行业案例，来自我做 AI 产品的真实工作流。`
- 说明：`每个案例只写当时的关键判断、工作流与评测口径；数字都来自项目记录。`
- 六个案例固定六块：场景 / 用户 / 关键判断（3 条） / 工作流 / 评测 / 可复用。
- 案例与核心判断：
  1. **AI 智能客服**：情绪兜底独立于业务意图；代词先补全再检索；长对话不能全量携带。
  2. **AI 会议纪要**：用户要的是「该关注什么」；先纠正 ASR 同音字再总结；先定模板再生成。
  3. **AI 拍照搜题**：先给结果后校验；题库冷启动先做录入工具；异常输入打标。
  4. **AI 陪伴**：人设是人格/记忆/能力/交互/伦理五件事；关系 0–100 映射行为边界；危机干预是必答题。
  5. **AI 问诊**：RAG 检索「问诊流程」；追问轮次封顶；四段固定输出便于质控。
  6. **AI 旅游规划师**：3 个追问题收敛需求；交通必须真实可查；评测不能只看均分。
- 评测数字：8 维 0/1/2 评分，均分 0.75 → 0.775（30 → 50 个样本），80 分以上占比 66.7% → 40% —— 只有均分升、优质率降的对比，才说明迭代方向要改。

### 5.4 关于页

- 状态：`AI 产品经理 · 成都 / 远程`（保留 `Open to AI PM roles` 兼容旧版英文时应同步本地化）
- 三段自述：① 10 年以上全栈经验，AI 产品经理，过去两年主导多智能体系统落地；② 工程出身先问边界，再做 AI 产品；③ 这个网站是知识地图与案例库，不是教程。
- 知识地图、能力维度：与 `/curriculum` 共用 `CurriculumPage` 数据，避免两处漂移。
- 工程故事：三个真实项目（广告素材 Agent 工作流 / AI Native 研发流程 / 广告业务数字化平台）。
- 方向：Agent / 效率工具 / 内容与社区类 AI 产品；早期到成长期；成都 / 远程。

### 5.5 文章页与其他

- 文章：标题「文章」，描述「工程手记，和 AI 产品复盘」；说明指向知识地图与实战案例。
- 摄影 / 搜索 / 树洞 / 管理后台：沿用既有文案，不做主题化改动（个人侧面，不承担产品叙事）。
- 404：`这条路径没有对应的产品需求。回首页，或者去看看知识地图？`

## 6. 内容口径与真实性

- 案例统一写成「我做过 / 我的评测口径」，不出现课程、老师、学员作业等语境。
- 案例里的数字按项目记录引用；不推导、不换算、不补样本；没有数据的写「没做长期跟踪 / 没做线上数据」，不编结果。
- 不写客户名称、合同金额、未公开的业务数据；不为凑故事新增项目。
- 个人经历、求职状态、时间线以本人确认为准；新增事实先确认再写。

## 8. 维护方式

- 改一句话：直接改 `messages/{zh,en}.json` 对应 key，同步两种语言。
- 加一个模块：在 `CurriculumPage.stages[].weeks` 增加对象；如涉及首页摘要，同步 `HomePage.knowledge.stages` 的方法标签。
- 加一个案例：在 `CasesPage.cases` 增加对象，六个字段齐全，数字必须有记录；首页预览从 6 个里选 3 个。
- 新增个人事实（客户、结果、时间线）：先确认再写，必要时在提交信息里注明来源。
