## 0. 这份文档解决什么

站点从「一个 AI 产品经理的自我介绍」升级为「一套可以点开看的知识地图 + 案例库」。主题来自课程材料：一套 13 周的 AI 产品经理训练体系。本文定义：

1. 站点讲什么、对谁讲、用什么语气讲；
2. 每个页面的静态文案结构（不是文章内容）；
3. 每条核心文案对应课程哪一部分材料，避免凭空写；
4. 哪些材料没有文字稿、不能写，哪些数字可以引用；
5. 后续改文案时，改哪里、保持什么规则。

## 1. 定位与主题

**一句话**：把 13 周课程的方法，变成一套能讲清楚、能被人验证的 AI 产品判断。

**主题**：一门面向转行者的 AI 产品经理课程（13 周，约 60+ 章节、6 个行业大案例）被重新组织为「4 个阶段、13 张卡片、6 个案例、1 套能力模型」，作为站点的主叙事与内容骨架。

**对外身份**：Max Zhang，十年全栈工程师，正在转向 AI 产品经理。网站不是课程笔记搬运，而是「我如何用这套体系重建产品判断」的证据页。

**希望访客记住的三件事**：

1. 他能把技术概念翻译成产品判断（场景、边界、评测、成本）。
2. 他有一套完整的方法地图，而不是零散知识点。
3. 他做过真实工程交付，能把方案和工程、算法聊到底。

**不承诺**：不得暗示已上完课程、获得证书、取得课程数据之外的成果；不得把课程案例包装成个人项目成果。涉及个人经历/求职状态的事实保持用户已确认口径。

## 4. 文案规则

### 从课程里继承的表达习惯

1. **先问场景，再谈模型**：每条判断都要有「什么情况下不适用」。
2. **用产品语言**：边界、取舍、评测、兜底、成本、交付、验证；不用「赋能、抓手、颠覆、革命性」。
3. **概念必须能被解释**：出现 RAG、MCP、Function Call、AB、灰度等术语时，配一句人话或放在方法标签里，不堆缩写。
4. **数字只引用课程材料明确给出的**：如「13 周」「4 阶段」「6 个案例」「106 条主诉」「8 维 0/1/2 评分」「V0.11 0.75 → V0.13 0.775，80 分以上 66.7% → 40%」「630 人 / 3 次 / 3 个月」。没有出处的数字不写。
5. **说法可验证**：写「材料未展开」而不是编结论；评测类文案写清样本与口径。

### 中文

- 短句，动词开头；能删的形容词都删。
- 标题偏判断句，正文偏解释句；不喊口号。
- 双语专名统一：AI 产品经理 / AI Product Manager；知识地图 / Knowledge Map；实战案例 / Case Studies。
- 按钮动词开头：看知识地图 / 看实战案例 / 打开完整地图 / 发邮件。

### English

- Sentence case, active voice, short sentences.
- Plain product English; avoid hype words.
- Mirror meaning, not word order; keep terms consistent with Chinese.

## 5. 页面文案（摘要，逐字以 JSON 为准）

### 5.1 首页

**Hero**

- eyebrow：`AI Product Manager · 2026`
- 主标题：`用 13 周课程，` / `搭一套产品判断。`（渐变）
- 导语：`十年全栈工程师，正在转向 AI 产品经理。我把一套 13 周课程的知识结构，重构成一张能用的能力地图——从提示词、评测、RAG、Agent，到需求、市场、数据，再到教育、客服、医疗、旅游的行业案例。`
- 主按钮：`看知识地图` → `/curriculum`；次按钮：`看实战案例` → `/cases`；文字按钮：`写邮件`
- 元信息：`01 / 背景 · 十年全栈工程 · 多智能体系统`｜`02 / 训练 · 13 周 AI 产品体系 · 6 个案例`｜`03 / 状态 · 正在寻找 AI 产品岗位 · 成都 / 远程`

**01 三条判断**

1. 先分场景，再选模型 —— 大模型擅长复杂、模糊、数据丰富的问题；高实时、零容错、简单大量的活，交给规则、小模型或者人。
2. 先写标准，再谈效果 —— 先定义什么算成功、失败怎么兜底、样本从哪里来；跑分高不等于产品能用。
3. 工程底子的价值是取舍 —— 把模型能力翻译成成本、风险和交付节奏。

**02 知识地图（4 个阶段）**

| 编号 | 周次  | 标题       | 一句话                                     | 方法标签                                                         |
| ---- | ----- | ---------- | ------------------------------------------ | ---------------------------------------------------------------- |
| 01   | W1–2  | 认知与原型 | 先把角色、模型边界和第一个 MVP 想清楚。    | 能力模型 / 大模型能力与幻觉 / 零代码 MVP / 提示词与评测          |
| 02   | W3–4  | 技术底座   | RAG 接知识，Agent 接行动。                 | 知识库五步 / 检索优化 / Function Call / MCP / 记忆与规划         |
| 03   | W5–8  | 产品全流程 | 从需求证据到 PRD，再到数据与合规。         | 访谈与问卷 / 市场选择 / PRD 与需求池 / 埋点 AB 灰度 / 沟通与合规 |
| 04   | W9–13 | 行业实战   | 把方法放进真实行业，最后写成可验证的项目。 | 教育答疑 / 智能客服 / 会议纪要 / AI 问诊 / 旅游规划 / 求职包装   |

**03 实战案例（3 个预览）**

1. AI 智能客服（零售 / 客服）——先分流，再回答；情绪兜底独立于业务意图。
2. AI 旅游规划师（旅游 / 规划）——用户要的不是信息，是一份能直接执行的方案。
3. AI 拍照搜题（教育 / 工具）——先给结果，再在后台校验题库答案。

**04 工作方式**：定义问题 → 画工作流 → 定评测 → 推落地；底行：`工程底子 · TypeScript · Python · Go · 多智能体（MCP / A2A）· 可观测性`。

**05 精选文章**：工程手记，和 AI 产品复盘。

**Now**：正在整理 13 周课程笔记和 6 个案例复盘，同时投递 AI 产品岗位。
**联系**：在找 AI 产品岗位。如果你们在做 AI 产品，或者想聊聊 Agent、RAG 与评测，欢迎直接邮件。

### 5.2 知识地图页（`/curriculum`）

- 标题：`知识地图`
- 副标题：`一套 13 周 AI 产品经理课程，被我重构成 4 个阶段、13 张卡片。`
- 说明：`内容依据课程讲义、提示词与案例材料整理。材料未覆盖的部分不补写；这里只保留能讲清楚的方法和判断。`

### 5.3 实战案例页（`/cases`）

- 标题：`实战案例`；副标题：`六个行业案例，来自课程的大案例工作流。`
- 说明：`结构依据课程工作流、提示词与附件整理；数字只引用材料中明确出现的，不做推测。`
- 六个案例固定六块：场景 / 用户 / 关键判断（3 条） / 工作流 / 评测 / 可复用。
- 案例与核心判断：
  1. **AI 智能客服**：情绪兜底独立于业务意图；代词先补全再检索；长对话不能全量携带。
  2. **AI 会议纪要**：用户要的是「该关注什么」；先纠正 ASR 同音字再总结；先定模板再生成。
  3. **AI 拍照搜题**：先给结果后校验；题库冷启动先做录入工具；异常输入打标。
  4. **AI 陪伴**：人设是人格/记忆/能力/交互/伦理五件事；关系 0–100 映射行为边界；危机干预是必答题。
  5. **AI 问诊**：RAG 检索「问诊流程」；追问轮次封顶；四段固定输出便于质控。
  6. **AI 旅游规划师**：3 个追问题收敛需求；交通必须真实可查；评测不能只看均分。
- 评测数字只出现在「AI 旅游规划师」：8 维 0/1/2 评分，V0.11 均分 0.75（30 样本）→ V0.13 均分 0.775（50 样本），80 分以上占比 66.7% → 40%。

### 5.4 关于页

- 状态：`Open to AI PM roles · 成都 / 远程`
- 三段自述：身份与转向 → 不是从零转行 → 用 13 周课程重建知识结构，网站是地图与复盘。
- 训练路径、能力维度：与知识地图页共用 `CurriculumPage` 数据，避免两处漂移。
- 工程故事：保留三个真实项目（广告素材 Agent 工作流 / AI Native 研发流程 / 广告业务数字化平台），作为「工程底子」证据。
- 求职方向：Agent / 效率工具 / 内容与社区类 AI 产品；早期到成长期；成都 / 远程。

### 5.5 文章页与其他

- 文章：标题「文章」，描述「工程手记，和 AI 产品复盘」；说明改为指向知识地图与实战案例，不再说「AI 产品笔记还在整理」。

## 7. 材料边界与真实性

- 课程中部分章节只有视频或图片型讲义（第 6 周设计理念 3 份 PDF、第 8 周合规篇、第 10–11 周部分章节、第 12–13 周视频），**没有文字稿**。站点不写这些细节，统一用「材料未展开」处理。
- 课程案例属于课程方与原始作者；站点表述为「来自课程工作流」，**不声称是个人项目成果**。
- 课程材料的数字只做原文引用；不推导、不换算、不补样本。
- 个人经历与求职状态沿用用户已确认的事实；新增个人信息（课程完成度、时间线、证书）需用户确认后再写。

## 9. 维护方式

- 改一句话：直接改 `messages/{zh,en}.json` 中对应 key，同步两种语言。
- 加一张周卡片：在 `CurriculumPage.stages[].weeks` 增加对象；如涉及首页摘要，同步 `HomePage.knowledge.stages` 的方法标签。
- 加一个案例：在 `CasesPage.cases` 增加对象，六个字段齐全，数字必须有出处；首页预览从 6 个里选 3 个。
- 改课程范围或来源：同步本文第 6、7 节，并在提交信息里注明材料来源。
