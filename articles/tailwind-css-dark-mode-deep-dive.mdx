最近升级 Tailwind CSS 到 v4 后，我碰上个问题：我的 GlassCard 组件在黑夜模式下“失灵”了。页面背景倒是变黑了，但这组件死活不肯变，还是浅色的。

这篇文章就是我在解决这个问题时的心得记录，希望能帮你理解 Tailwind CSS v4 的黑夜模式、CSS 变量覆盖机制，还有几个容易混淆的 CSS 概念。

## 1. 案发现场：GlassCard 失效之谜

### 现象

我在页面中使用了一个 `GlassCard` 组件，代码大致如下：

```tsx
<div className="bg-white/40 dark:bg-black/40 border-white/20 dark:border-white/10 ...">{/* 内容 */}</div>
```

同时，我使用了 `next-themes` 来管理主题切换，配置如下：

```tsx
<ThemeProvider attribute="class" defaultTheme="system">
```

**结果**：

- 当我点击切换按钮，页面的背景色（由 `body` 控制）成功变黑了。
- 但是，`GlassCard` 的背景依然是 `bg-white/40`，导致在深色背景上极其刺眼。

### 为什么会这样？

问题出在 Tailwind CSS v4 和 v3 的一个关键区别上。

**在 v3 时代**，我习惯在 `tailwind.config.js` 里写 `darkMode: 'class'`。这告诉 Tailwind：“嘿，只要看见 HTML 标签上有 `.dark` 类名，就激活 `dark:` 样式。”

**而在 v4 时代**，Tailwind 默认采用了**媒体查询（Media Query）**策略。也就是说，它生成的 CSS 规则类似于：

```css
@media (prefers-color-scheme: dark) {
  .dark\:bg-black\/40 { ... }
}
```

这意味着：**Tailwind 只听操作系统的指挥**。如果你的系统是浅色模式，哪怕你的网页 HTML 已经被 `next-themes` 加上了 `.dark` 类，Tailwind 也视而不见。

### 修复方案：@variant

想让 Tailwind v4 重新认 `.dark` 类，就得在 CSS 里明确定义这个变体。

在 `app/globals.css` 中添加：

```css
@variant dark (&:where(.dark, .dark *));
```

**这句话的翻译是**：
“Tailwind，请定义一个叫 `dark` 的变体。它的生效条件是：当前元素要么自己有 `.dark` 类，要么是 `.dark` 类的后代。”

加上这行代码后，Tailwind 就会生成基于类的 CSS 选择器，从而配合 `next-themes` 完美工作。

## 2. 为什么有的组件没坏？（CSS 变量的魔法）

你可能会问：“既然 `dark:` 失效了，为什么页面背景（body）却能正常变黑呢？”

这是因为 `body` 的颜色切换根本没用到 Tailwind 的 `dark:` 变体，而是纯靠 **CSS 变量（Custom Properties）**。

看看 `globals.css`：

```css
:root {
	--background: #ffffff;
}

.dark {
	--background: #09090b; /* 变量被重写了 */
}

body {
	background-color: var(--background);
}
```

**简单来说就是**：

1. `next-themes` 给 `<html>` 加上了 `.dark` 类。
2. CSS 变量 `--background` 在 `.dark` 类下被重新定义了。
3. `body` 用的 `var(--background)` 就自动变成了黑色。

这完全是 CSS 自己的事儿，跟 Tailwind 没关系，所以 Tailwind 版本升级影响不到它。

## 3. 核心概念辨析

解决这个问题的过程中，有几个词儿老是出现，容易搞混，我理了理：

### Variant (变体)

“变体”这个词在前端里用的地方挺多，但意思不太一样：

- **Tailwind 里的 `hover:`, `dark:`**：这种是**状态变体**。就是“鼠标放上去变个色”、“黑夜模式换个背景”这种。
- **组件库里的 `variant="outline"`**：这种是**样式变体**。就是“我要按钮的描边版本，不要填充的”。
- **CSS 里的 `@variant`**：这个是**定义变体条件**。就是告诉 Tailwind：“什么时候该用这个变体”。

### Layer (层级)

Tailwind 把样式分成三层，主要是为了控制谁先谁后：

1.  **Base (`@layer base`)**：**打底用的**。
    - 重置那些 HTML 标签的默认样式，比如 `h1` 的字体大小、`a` 的下划线。
    - _说白了就是_：全站统一的默认设置。

2.  **Components (`@layer components`)**：**组件用的**。
    - 把一长串 Tailwind 类打包成一个类，比如 `.btn`, `.card`。
    - _说白了就是_：给常用的样式组合起个短名字。

3.  **Utilities (`@layer utilities`)**：**工具类**。
    - 就是那些 `.p-4`, `.flex` 这种原子类。
    - _说白了就是_：调细节的小工具。

### Attribute="class"

`next-themes` 的这个配置项很重要，它决定了主题切换的“开关”怎么装。

- **`class`**：在 `<html>` 标签上加删 `class="dark"`。最常用，兼容性最好。
- **`data-xxx`**：在 `<html>` 标签上改 `data-theme="dark"`。某些组件库（如 DaisyUI）偏爱这种。

## 总结

通过这次 Debug，我搞明白了几个关键点：

1.  **Tailwind v4 默认只看系统设置**，想用 `next-themes` 就得手动加 `@variant`。
2.  **CSS 变量** 是另一条路，它不依赖 Tailwind，所以不受版本升级影响。
3.  **搞清楚工具怎么工作的**（比如 `@layer`, `@variant`），下次再遇到这种“灵异现象”就知道该查哪儿了。

希望这个经验能帮你少踩点坑。
